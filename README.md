# AI-помощник для карточек КИП

Локальный прототип. По JSON контрольно-измерительного прибора собирает черновик карточки для B2B-магазина: SEO-заголовок, SEO-описание, характеристики, поисковые запросы и короткий блок для менеджера.

Заголовок и поисковые запросы предлагает модель. Описание, характеристики и блок для менеджера код собирает из входных фраз. Новые технические числа туда не попадают.

## Что нужно

- Python 3.12 или новее
- Ключ любого OpenAI-совместимого API

Веб-форма, база, админка и деплой не входят в прототип.

## Запуск

```bash
make install
cp .env.example .env
# Вписать AI_API_KEY с https://console.groq.com/keys
# По умолчанию Groq и openai/gpt-oss-120b: этот адрес открывается из РФ.
make examples
```

Один товар в stdout:

```bash
make run
```

Свой файл:

```bash
.venv/bin/python -m app.cli path/to/product.json --output examples/card.md --json-output examples/card.json
```

`--format json` печатает JSON вместо Markdown. Каталоги для `--output` создаются сами.

Коды выхода: `2` — битый или чужой JSON, `3` — сбой API или пустой ключ, `4` — ответ модели не прошёл проверку.

## Вход

```json
{
  "name": "Манометр показывающий DM 02",
  "manufacturer": "Манотомь",
  "specs": {
    "диапазон измерений": "0–1,6 МПа",
    "класс точности": "1,5"
  },
  "description": "Прибор предназначен для измерения избыточного давления.",
  "source_url": ""
}
```

`source_url` хранится в файле для человека и в промпт не попадает. Пустая строка в поле или в значении характеристики — пробел. Неизвестное поле JSON отклоняется, чтобы факт не потерялся молча.

В `fixtures/` лежат два товара с [pribor.ru](https://www.pribor.ru):

| Файл | Страница | Зачем |
|---|---|---|
| `fixtures/cem-dt-8890a.json` | [CEM DT-8890А](https://www.pribor.ru/product/kontrolno-izmeritelnoe-oborudovanie/izmeriteli-parametrov-okruzhayushchey-sredy/izmeriteli-davleniya-barometry/differentsialnyy-manometr-cem-dt-8890a/) | Полная таблица. В тексте страницы максимум 60 кПа, в таблице 137,9 кПа. Оба числа сохранены, третье не выбирается |
| `fixtures/cem-dt-8897.json` | [CEM DT-8897](https://www.pribor.ru/product/kontrolno-izmeritelnoe-oborudovanie/izmeriteli-parametrov-okruzhayushchey-sredy/anemometry/anemometr-differentsialnyy-manometr-cem-dt-8897/) | Питание и температура хранения на странице не указаны, во входе пустые |

На странице DT-8890А в слове «а также» стояла латинская `a`. В фикстуре она заменена на русскую «а».

## Результат

Markdown удобно копировать. Внизу служебная строка с длинами: заголовок до 70 символов, описание 800–1 200. Пробелы считаются. У пустой характеристики значение `данных нет`. Блок «Чего не хватает во входе» повторяет пустые поля.

JSON той же карточки пишется флагом `--json-output`.

## Промпт и проверки

Текст промпта — `app/prompt.py`.

Модели запрещено:

- добавлять строки характеристик, которых нет в `specs`;
- менять единицы и округлять;
- подставлять отрасль, стандарт, цену, артикул, пылевлагозащиту или интерфейс, если этого нет во входе;
- выбирать третье число, если страница сама себе противоречит.

`app/checks.py` после сборки проверяет длины, состав характеристик и числа. Число в заголовке и запросах должно уже быть в названии, производителе, описании или значении характеристики. Разделитель тысяч не считается новым числом: `9 970` и `9970` — одно значение. Если в ответе нет JSON, модели уходит одна правка. Сетевой повтор на это не тратится.

Повтор запроса есть только при таймауте, обрыве сети и статусах 429, 500, 502, 503, 504. Ключ читается из `AI_API_KEY` или `.env`. В коде и в логе его нет.

Температура по умолчанию `0.2`.

## Ограничения

- Длину и список характеристик держит код. Описание и блок для менеджера состоят из фраз входа, поэтому пересказ модели и склеенные слова туда не попадают. Отрасли вроде лаборатории, производства и вентиляции в заголовке и запросах выкидываются, если их не было во входе. Если модель дважды не прислала JSON, черновик собирается из входных полей.
- Объём описания 800–1 200 символов длиннее текста паспорта и длиннее обычного meta description. Это текст карточки, как в задании. Недостающие символы добираются повтором уже известных фраз, а не новыми фактами.
- Нет веб-формы, очереди, базы и обхода каталога. Страницы pribor.ru разобраны в фикстуры вручную.
- Если собранный черновик всё же не проходит проверку, команда заканчивается кодом 4 и списком ошибок. Готовый черновик в этом случае не записывается.
- Локальный OpenAI-совместимый сервер подходит: в `.env` меняются `AI_BASE_URL` и `AI_MODEL`. Отдельный хаб в этот репозиторий не встроен.

Сопроводительное письмо — `letter.md`.
